# Measurement results

The data behind [docs/performance.md](../../docs/performance.md), as compact tables.
[`../performance.ipynb`](../performance.ipynb) reads only these files, recomputes every
figure the doc quotes and draws every chart. [`../extract.py`](../extract.py) made them
from the live harness's raw run files, which stay on the machine they were recorded on.

Every timed sample is kept, one row each, so a mean, a standard deviation, an outlier
or a round-by-round drift can be checked here rather than taken on trust. Times are
milliseconds unless the column says otherwise. Booleans are `true` and `false`.

The three vaults:

- **bench**: generated by [`../live/genvault.py`](../live/genvault.py), 20,000 one-line
  notes, measured with the author's settings (age filter keeps 4,168) or Obsidian's
  defaults where a file says so.
- **demo**: the 112-note demo vault, with Pulsar as its only plugin.
- **the author's vault**: about 1,100 notes and 31 plugins. Only aggregates leave it,
  in `authors-vault.csv`; nothing that names a note, a folder or another plugin.

## Builds

`builds.csv` — every build measured. The three releases carry the sha256 of their
`main.js`, which matches GitHub's digest for the release asset. The first session's
pull-request builds were built from their branches and never hashed; `commit` is the
merge commit, for reference only.

## `restyle/` — the fresh-writing reconfigure, solved, 8 October 2026, 02:38–02:46

`loads.csv`, one row per plugin load in the demo vault with fresh writing on and six
editors open, measured by [`../live/restyle.mjs`](../live/restyle.mjs). Every pending
restyle is forced (`document.body.offsetHeight`) and timed at fixed points, so no build
can leave one for an untimed frame. `comparison` is `orders` (1.38.0, the 1.40.0 code
path, and that path with the properties set after the call) or `fix` (before #125 and
1.41.0); each is the second of two rounds, the first having been printed and not kept.
Columns: `calls` and `reconfigure_ms`, the `workspace.updateOptions` calls and their
time; `restyle_from_properties_ms`, the restyle forced right after fresh writing's last
body property is set; `restyle_pending_before_call_ms` and
`restyle_pending_after_load_ms`, whatever else was pending before each call and at the
end of the load; `total_ms`, the four together; `enable_ms`, `enablePlugin` until it
resolved, which the forced restyles lengthen.

## `authors-vault.csv`

Aggregates from the author's vault only: `metric`, `build`, `unit`, `n`, `mean`, `sd`
(sample sd), `median`, `source_label` (the raw file it came from), and `graphs_open`
(which graphs were open and how many nodes each held; "hidden" means a background tab
that did not draw). Two rows come from the load profile: the time per load under
Obsidian's `addDropdown`, and the part of it spent reading `offsetWidth`.

## `flame/`

`*.folded.gz` are CPU profiles from the Chrome DevTools profiler (100 µs sampling, on
an unminified build so that frames carry names), folded into one line per distinct
stack: `frame;frame;frame microseconds`. Each sample is weighted by the time it
covered, idle time is dropped, and each frame carries the last segment of its file in
brackets. `zcat` reads them. `profiles.csv` says what each one is: `source_label`,
`vault`, `build`, what one `event` is and how many `events` the profile covers,
`busy_ms`, `idle_ms`, `duration_s`.

## `vitest.csv`

`npm run bench`, three runs back to back on 8 October 2026 under WSL2 on the same
laptop (Node 20.19.3, vitest 3.2.7): per benchmark `n` samples, `mean_ms`, `sd_ms`,
`median_ms`, `p99_ms`, `min_ms`, `max_ms`.

## `pr-only.csv` and `published.csv`

`pr-only.csv` lists figures the harness printed during a session and a pull request
quoted, but that were never written to disk. Nothing here can recompute them.
`published.csv` lists what the release notes first said, for the notebook to set
beside the raw data.
